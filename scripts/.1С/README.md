# Деплой изменений в тестовую ИБ 1С

Готовый набор PowerShell-скриптов для командной загрузки конфигурации 1С
(выгруженной в XML — `/LoadConfigFromFiles`) в тестовую информационную базу,
со статическим контролем BSL перед обновлением базы. Задачи в этих скриптах —
это те самые задачи, которые ищет расширение
[qazdefense-1c-tools](https://marketplace.visualstudio.com/items?itemName=qazdefense.1c-tools)
на вкладке «1С: проект» (кнопка «Задачи»), но скрипты полностью самостоятельны
и работают без расширения — просто из PowerShell или `.vscode/tasks.json`.

## Установка

Скопируйте всю папку `.1С/` из этого набора в корень своего репозитория с
конфигурацией 1С. Ожидаемая структура репозитория:

```
<репозиторий>/
  .1С/                          ← эта папка
  Configurations/
    <ИмяБазы>/
      Configuration/            ← XML-выгрузка конфигурации (DumpConfigToFiles)
      Extensions/
        <ИмяРасширения>/        ← XML-выгрузка расширения, если есть
```

Если баз/расширений несколько — у каждой своя папка под `Configurations/`.

## Файлы

- `config.psd1` — реальные настройки (путь к ИБ, платформа, логин/пароль). Добавьте в `.gitignore`, не коммитьте.
- `config.example.psd1` — шаблон настроек с комментариями, коммитится в репозиторий.
- `common.ps1` — общая часть остальных скриптов (чтение config, аргументы подключения, статический анализ BSL, опциональные Telegram-уведомления). Не запускается напрямую.
- `deploy-to-ib.ps1` — загрузить изменённые объекты конфигурации в ИБ (+опционально обновить БД).
- `update-db.ps1` — только обновить конфигурацию базы данных (`/UpdateDBCfg`), без загрузки файлов — когда конфигурация в ИБ уже актуальна.
- `open-designer.ps1` — открыть Конфигуратор 1С (GUI) для той же ИБ.
- `open-enterprise.ps1` — запустить 1С:Предприятие (GUI) для той же ИБ.
- `dump-config.ps1` — выгрузить конфигурацию (или расширение) ИБ в XML для сверки после деплоя.
- `switch-base.ps1` — переключение между несколькими базами без ручной правки `config.psd1` (см. ниже).
- `bots/default.psd1.example` — шаблон Telegram-уведомления о деплое, полностью опционально.
- `logs/` — логи запусков `1cv8.exe` и JSON-receipt'ы деплоев (создаётся сама, добавьте в `.gitignore`).

## Первоначальная настройка

1. Скопировать `config.example.psd1` → `config.psd1`.
2. Заполнить в `config.psd1`: тип подключения (File/Server), путь к ИБ или сервер+база, путь к `1cv8.exe`, логин/пароль (если нужны).
3. Опционально — уведомление в Telegram после деплоя: завести бота через `@BotFather`, узнать `chat_id` (например через `@userinfobot`), скопировать `bots/default.psd1.example` → `bots/default.psd1` и заполнить `BotToken`/`ChatId`. Ничего не заполнили — уведомления просто не отправляются, остальное работает как обычно.

## Несколько баз — переключение без ручной правки config.psd1

`config.psd1` активен только для одной базы за раз. Чтобы не редактировать
его руками при каждом переходе между базами, заведите отдельный профиль на
каждую базу и переключайтесь скриптом `switch-base.ps1`:

```powershell
# 1. Завести профиль новой базы (один раз)
Copy-Item .1С\config.example.psd1 '.1С\base-profiles\ИмяБазы.psd1'
# ...заполнить ConfigBase/ConnectionType/File или Server/Auth внутри...

# 2. Посмотреть, какие профили есть и какой активен
.\.1С\switch-base.ps1 -List

# 3. Переключиться
.\.1С\switch-base.ps1 -Name ИмяБазы
```

Профили `base-profiles/<Имя>.psd1` — как и сам `config.psd1` — держите вне
git (там может быть пароль конкретной базы; у некоторых ИБ логин/пароль
пустые — это нормально, не у всех есть авторизация). То же самое доступно
визуально из панели «Базы проекта» расширения qazdefense-1c-tools.

## Использование

```powershell
# 1. Загрузка изменённых данных
.\.1С\deploy-to-ib.ps1                # загрузить только изменённые объекты
.\.1С\deploy-to-ib.ps1 -Base HEAD~1    # сравнить не с HEAD, а с другим коммитом
.\.1С\deploy-to-ib.ps1 -All            # загрузить всю конфигурацию целиком

# 2. Загрузка и обновление БД
.\.1С\deploy-to-ib.ps1 -UpdateDb       # + обновить конфигурацию базы данных (/UpdateDBCfg)
                                        # (перед этим - автоматически CheckModules + CheckConfig)
.\.1С\deploy-to-ib.ps1 -UpdateDb -SkipCheckModules   # без статического контроля BSL
.\.1С\deploy-to-ib.ps1 -UpdateDb -SkipCheckConfig    # без проверки целостности конфигурации

# Явный список файлов вместо диффа с git (например, в грязном worktree)
.\.1С\deploy-to-ib.ps1 -Extension МоёРасширение -FileListPath .\deploy-files.txt -PlanOnly
.\.1С\deploy-to-ib.ps1 -Extension МоёРасширение -FileListPath .\deploy-files.txt -UpdateDb

# 3. Просто обновление БД (без загрузки файлов)
.\.1С\update-db.ps1

# 4. Запуск Конфигуратора
.\.1С\open-designer.ps1

# 5. Запуск Предприятия
.\.1С\open-enterprise.ps1
```

Без `-Files`/`-FileListPath` изменённые объекты определяются как: diff с
`-Base` (по умолчанию `HEAD`) + staged + untracked файлы. Скрипт отклоняет
файлы вне выбранной конфигурации/расширения и по умолчанию блокирует
загрузку более 200 объектов за раз (обход — `-AllowWideDeploy`, только для
осознанного широкого деплоя). До запуска `1cv8.exe` preflight также
проверяет, что рассчитанные объекты метаданных существуют, XML
синтаксически корректен, а изменённые BSL-модули являются корректным
UTF-8 текстом.

### Два гейта перед обновлением базы

Перед `/UpdateDBCfg` (в `deploy-to-ib.ps1 -UpdateDb` и в `update-db.ps1`)
автоматически запускаются два независимых гейта 1cv8.exe, оба сканируют
конфигурацию/расширение ЦЕЛИКОМ — режима «только изменённые файлы»
платформа не даёт ни для одного из них.

**1. `/CheckModules -Server -ThinClient`** — статический синтаксис-контроль
BSL (~25–30 секунд на конфигурации среднего размера). Находит ошибку
модуля до того, как она попадёт в применяемую к базе конфигурацию, а не по
факту сбоя `/UpdateDBCfg` или в рантайме у пользователя.

Для расширений диагностика "Переменная не определена" на член
расширяемого (не заимствованного) объекта — известное ложное
срабатывание платформы (статический анализатор не видит общее
пространство имён с базовым модулем, которое существует только в
рантайме) и не блокирует деплой; любая другая диагностика блокирует.
Отключить: `-SkipCheckModules`; сузить/расширить набор режимов проверки:
`-CheckModulesModes @("-Server")`.

**2. `/CheckConfig -ConfigLogIntegrity`** — платформенная проверка
логической целостности конфигурации: ссылки метаданных, права, формы —
без разбора кода модулей, отдельная команда от `/CheckModules` (~5–10
секунд, заметно дешевле). Платформа сама описывает её как «стандартную
проверку, обычно выполняемую перед обновлением базы данных». Флаг
`-IncorrectReferences` намеренно не подключён — на конфигурациях с БСП он
даёт известный шумный класс диагностик («Справка Неразрешимые ссылки на
объекты метаданных» — битые ссылки на темы контекстной справки, не
функциональная ошибка), а надёжного признака для его понижения пока нет.
Любая диагностика `-ConfigLogIntegrity` блокирует. Отключить:
`-SkipCheckConfig`.

Результат каждого гейта попадает в JSON-receipt деплоя
(`.1С/logs/deploy-receipts/`, поля `check_modules`/`check_config`: `ok`,
`exit_code`, `blocking`, у `check_modules` ещё и `downgraded`) вместе с
базой/расширением, файлами, объектами, режимом `UpdateDBCfg` и кодами
возврата — без паролей и строки подключения.

## VS Code: task, Command Palette и хоткей

Расширение [qazdefense-1c-tools](https://marketplace.visualstudio.com/items?itemName=qazdefense.1c-tools)
ожидает задачи именно с такими именами в `.vscode/tasks.json`:

- `1С: Загрузить изменённые объекты`
- `1С: Загрузить изменённые объекты + обновить БД`
- `1С: Обновить конфигурацию БД`
- `1С: Открыть Конфигуратор`
- `1С: Запустить Предприятие`

Пример `.vscode/tasks.json`:

```jsonc
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "1С: Загрузить изменённые объекты",
      "type": "shell",
      "command": "powershell",
      "args": ["-ExecutionPolicy", "Bypass", "-File", "${workspaceFolder}/.1С/deploy-to-ib.ps1"]
    },
    {
      "label": "1С: Загрузить изменённые объекты + обновить БД",
      "type": "shell",
      "command": "powershell",
      "args": ["-ExecutionPolicy", "Bypass", "-File", "${workspaceFolder}/.1С/deploy-to-ib.ps1", "-UpdateDb"]
    },
    {
      "label": "1С: Обновить конфигурацию БД",
      "type": "shell",
      "command": "powershell",
      "args": ["-ExecutionPolicy", "Bypass", "-File", "${workspaceFolder}/.1С/update-db.ps1"]
    },
    {
      "label": "1С: Открыть Конфигуратор",
      "type": "shell",
      "command": "powershell",
      "args": ["-ExecutionPolicy", "Bypass", "-File", "${workspaceFolder}/.1С/open-designer.ps1"]
    },
    {
      "label": "1С: Запустить Предприятие",
      "type": "shell",
      "command": "powershell",
      "args": ["-ExecutionPolicy", "Bypass", "-File", "${workspaceFolder}/.1С/open-enterprise.ps1"]
    }
  ]
}
```

**Command Palette:** `Ctrl+Shift+P` → **Tasks: Run Task** → выбрать нужный
пункт по названию — либо запускать те же задачи прямо из вкладки «1С:
проект» расширения.
